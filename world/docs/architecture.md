# 页面、场景与资源架构

状态：静态预览已接续；下文为首期方案 v1 的架构基线，尚待实施与实测。

## 当前页面

`src/pages/world.astro` 仅导入 `world/components/WorldPage.astro`。
页面直接展示唯一参考原图，提供返回博客入口，不加载旧样板、v11 或旧发布资源。
原图当前作为静态预览输出，不代表正式首屏资源预算已通过。
博客只保留通往 `/world/` 的入口，不预加载世界资源。

旧 `runtime/`、`scripts/` 与清单暂留作工程记录，未在本轮改写或迁移。
其中的旧素材路径已失效；旧生成命令不可运行，未来实施时再评估代码复用和退役。

## 已确定的主方向

Astro 承载独立路由、元信息、回退和少量 UI；PixiJS 负责二维场景组织与渲染。
不增加经营、任务、库存、复杂物理或完整生产模拟。
PixiJS 尚未安装，当前页面没有新场景运行时。

计划职责：镜头与输入、按区域的资源加载、动作片段与轻量调度、
绘制与前后关系、暂停与资源回收。源工程和运行时的数据接口先用小样验证。

## 场景与加载

观看优先局部可读，首期完整农村约 4–5 个桌面默认视野宽度。
起始镜头围绕院落—菜园—田渠，手机竖屏显示可读的局部，拖动浏览同一场景。
不把全景塞入初始视野，不以无限放大作为高精度原画的交付要求。
缩放边界、世界坐标和像素规格由总构图与局部样片确定。

美术上连续，发布时分区域和分块。远景底图用于缩小观察与加载过渡，
正常视野和附近区域加载相应细节；最大缩放由源稿实际精度决定。
背景、少量动态主体与必要前景承担明确职责，静态物件不逐件对象化。

只优先加载起始视野，预取邻近内容。快速移动时优先当前视野，
取消或降低过时请求的优先级；远离区域后释放解码资源，保留浏览器文件缓存。
解码缓存按估算字节数控制，不能只按图片数量限制。

只更新和绘制可见动态，回来时按统一动作时钟恢复相位；
后台、暂停和离开页面时停止无用刷新，离开后释放资源。
缓存稳定内容，控制画布实际像素数和高分屏开销，区分镜头刷新与动作采样率。

提供渐进加载、失败后重试与静态观看回退，保持返回入口可用。
首期无音频资源与播放系统；不实现季节切换、昼夜时钟或天气模拟。
未来季节设想通过保存源工程与布局记录保留，不提前建设切换框架。

## 发布与维护

- imagegen 原稿、部件、Blender 工程与原始动作帧留在美术源目录。
- `public/world/` 只放正式发布素材和小型清单，按区域或主体拆分，不打成全世界巨型图集。
- 背景测试有损 WebP；透明动作测试无损/近无损 WebP，检查轮廓、细线和透明边缘。
  编码选择同时比较下载和解码，不只选文件最小的格式。
- 清单包含共同坐标、图片规格、锚点、动作时长与版本；必要时包含步幅与方向。
- 调整某一角色或区域仅重导相关资源。使用内容版本路径，避免缓存加载旧素材。

## 初步验证预算

| 指标 | 试验目标与口径 |
| --- | --- |
| 首屏图片和动作下载 | 约 2–4 MiB，其余随探索加载；不是已测结果 |
| 移动端常驻解码素材 | 先按 64–96 MiB 控制；画布、GPU 副本和浏览器开销另计 |
| 流畅度 | 桌面争取接近 60 帧/秒，目标手机稳定 30 帧/秒，单独检查镜头操作 |
| 长时间探索 | 来回跨区域后缓存稳定、内存不持续增长 |

最终资源体积、实际内存和设备兼容性须实测，不承诺所有设备同样流畅。
检查桌面、真实手机、弱网、缩放与拖动、暂停、后台、博客往返及反复进入。
窄屏窗口只验证布局；CPU 绘制耗时也不能代替实际呈现性能。
