# 制作推进与阶段验收

更新：2026-10-13。作者同意进入制作，并要求 Codex 负责质量、作者负责验收与调整。
首期方案 v1 继续作为内容基线，见 [需求](redesign.md)与[场景方案](rural-scenes.md)。

## 分工与交付方式

Codex 维护原画、角色与动作源工程、资源导出和网页，负责制作、自检与返工。
作者验收画风、内容、疏密、生活氛围和观看感受，可提出保留与调整意见。
作者不需要指定像素坐标、每个物件的动作或动画参数。

每次交付说明版本、用途、完成范围、自检结果及尚未验证的项目。
先修正已发现的明显问题，再提交当前阶段可讨论的结果。
记录作者反馈与验收状态，不能把「已生成」「检查通过」写成「作者已验收」。
在已有授权范围内主动迭代，不重复要求开始同一阶段的许可。
涉及整体画风、地区用途或首期范围改变时回到方案讨论。

## 推进顺序

| 阶段 | Codex 交付与自检 | 作者验收重点 |
| --- | --- | --- |
| 全农村构图 | 总览草稿、正式长卷的布局与起始视野；检查八区、地形、道路水系、尺度和衔接 | 区域安排、三处生活节点、疏密、整体氛围与风格 |
| 院落静态局部 | 院落—菜园—水渠背景与独立居民、鸡；检查统一比例、笔触、光照、落地和遮挡 | 局部画面质量、角色与环境是否协调、细节是否丰富而清楚 |
| 院落动态样片 | 有限生活动作、可编辑 Blender 工程与网页交付验证；检查接触、落脚、启停、循环、资源成本与设备表现 | 正常速度的自然感、动作轻重与停顿、是否安静而有活性 |
| 完整农村 | 沿相邻土地完成八区，组织全场动静并完成加载、缓存、回退与设备检查 | 内容完整性、长期观看的协调感、跨区衔接和最终体验 |

阶段结果按作者反馈调整，本阶段交付范围与验收条件通过后推进下一阶段。
整体方向认可不能替代完整布局、内容覆盖和观察尺度的检查。
局部样片同时验证观感与资源成本，合格方法再扩展到农村其他区域。
具体内容验收条件见 [需求中的交付与验收](redesign.md)。

## 质量检查重点

- 美术：始终以唯一原始参考为画风基准；新稿保持一致的视角、光向、比例与轮廓。
  总览用于构图，正式局部还需在默认观察尺度检查。
- 空间与内容：八区主要用途清楚，道路通到实际出入口，桥宽符合使用对象，
  田、塘、坡地与住家位置可信；作物状态遵守同一个初夏时段。
- 动作：检查重心、手与物件接触、脚的落点、位移和遮挡。
  明显滑步、闪烁或纸片感要修正原因，不能用叠化或加帧掩盖。
- 协调：在默认视野整体看，保留安静段与停顿，不给每个区域安排持续劳动。
  暂停后仍能通过物件和空间看懂生活与产业关系。
- 网页：代码检查、实际页面检查和观感检查分别记录。
  真实手机、电脑、弱网、拖动缩放、暂停、后台和反复进入按阶段实测。
  初步预算见 [架构](architecture.md)，当前未得到新场景的性能结果。

质量通过以具体图稿、正常速度样片和设备实测为依据。
未验证的手部动作、步态和导出链路先在样片中解决，
不把文档定稿、图片生成或工程构建成功当作它们已经合格。

| 动作与性能 | 尚未制作、接入或测量；本次没有修改页面与运行代码 |
| 作者反馈 | 整体方向基本认可；指出细节需真实、内容不够丰满并要求核对全长。完整布局、细节与丰满度尚未通过验收 |

原始参考文件与哈希保持不变。v1、v2 是本次新制作的草稿版本，
不重新启用已退役素材，也不把构图草稿当成第二张画风标准。
