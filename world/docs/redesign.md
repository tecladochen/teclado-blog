# 需求与边界

## 当前有效需求 · 农场重设计

2026-10-13，作者回看夜间成果后指出后续图片未正确接续、流程过慢、道路水系与碎景过多，要求重新设计农场生态结构和产业内容。
保留纵向三图容量，重新组织完整田地、果园、生产后场与生活空间；道路和水系按实际用途安排。
先完成内容方案与实现方案，确认后出风格图，风格确认后批量生产，完整效果确认后再优化性能。
优先试无冗余重叠的有效图直出，能否丝滑接续须用相邻小样验证，不能提前保证。
开发调试阶段采用原始 PNG 快速预览，不要求每次先做 Sharp、WebP 和复杂导出。
PC、全屏、拖动有限缩放、简洁控制、初夏江南与首期无声的观看目标保留。

作者进一步明确设计范围为更大的乡村：多种种植养殖、加工手艺、完整村落与公共生活共同展开。
鱼塘、鸡鸭、牛羊等典型产业需要充分表达；人文环境加入后不缩减产业范围。
长度与篇幅不设硬上限，按实际内容和环境关系增加横向空间，第一版田地果园面积占比撤回。
公共场所由 Codex 依据居民与生产生活需求自主选择、布局和协调，小集市、小卖部、村委会广场仅为作者举例。
七片空间、具体产业组合、公共设施和住宅数量属于当前提案，尚待作者审阅。
作者最新要求由 Codex 严格审核内容合理性、丰富度、完整性与具象细节，再逐步考虑风格参照图。
自审、样片验证与作者视觉验收分别记录，不能把文字设计完整写成实际画面合格。

作者已明确确认村心园艺 v3 与牛羊草料 v3 两张参考为本轮画风基础，参考角色相似可接受，正式居民须多样化。
后续推进见 [阶段计划](rural-production-plan-v3.md)：总平面细化、相邻接续和三图高度样段、原始 PNG 预览、样段确认后分批生产、完整效果确认后优化。
本轮 [内容与实现方案](farm-redesign-v3.md)中的精确构图和生产规格仍待验证；旧 v2 仍在页面供问题对照，未通过作者视觉审核。
旧自动续做已暂停，旧空间与固定重叠规格被本轮反馈替代，不继续自动扩展到小镇。

## 观看目标

访客进入一片连续、统一、内容丰富的手绘生活世界，可以拖动、有限缩放和安静停留。
以观看为主，交互简单直觉，无需经营、安排生产、完成任务或承担离开的损失。
动态用于让画面有活性，整体协调比动作数量与表现强度更重要。

作者描述需求并验收效果，Codex 负责设计、制作工程、自检和返工。
《清明上河图》仅说明横向长幅形式，不参考其时代、内容或叙事安排。
产业和生活线索用于组织可信场所，不自动转成库存、产量、离线结算或完整劳动模拟。

## 内容基线与设计自由

作者认可新空间方案并保留八类内容：村居院落、近宅菜园育苗、稻田旱豆与田渠、果茶坡与蜂箱、
竹木菌菇与编作、鱼塘荷岸与鸭水、畜禽草料、共用农务与村口。
它们从地势、生活中心、生产和通行关系重新组织，不强制八块独立区域，
也不由图片分块决定功能边界。已确认布局和通行灌排见 [农村规划](rural-scenes.md)。

[场景设计](rural-scenes.md)的整体空间已确认；具体作物、器具、居民数量、
节点数量和精确物件坐标仍由 Codex 细化，须符合时代、季相与真实用途。
作者举例的店铺、工厂、图书馆、海洋馆、办公楼、机场、码头不构成本期必做清单。
土地、水面、路边空地与林缘承担疏密和连接，也需要完整设计。

原图尺寸、纵向数量、重叠及去重发布规格已获得作者确认，固定执行。
横向列数按内容需要确定；精确物件坐标、屏幕标尺、编码质量、动作工具、
请求调度、帧率与资源预算仍是实施细化或试验参数，不是已验证结果。
在核心目标内由 Codex 校准，不能用缩小物件、删除特色或复制素材降低制作成本。

## 验收口径

| 范围 | 通过条件 |
| --- | --- |
| 整体空间 | 八类内容用途可辨，土地、道路、水系和地势连贯；左侧完整、自然收尾，上下用途充分 |
| 丰富性与真实性 | 各处用途和组合不同，作物季相、设施、通行与灌排可信；静止时也有内容可看 |
| 观看 | 默认看全上下，最小处停止缩小，最大处清楚；局部可读，拖动缩放直觉 |
| 拼合 | Codex 先核对定位、裁边、重叠和覆盖，检查整段、所有接缝及放大细节；根据实际问题确定处理方式，原图有差异时另行判断修图需求 |
| 动态 | 主体接地、接触与遮挡可信，正常速度无明显滑步、闪烁或重影，启停与节奏自然 |
| 界面 | 画面为主，少量必要控制；预览辅助控件不成为最终常驻界面 |
| 运行 | PC 检查首次加载、连续拖动缩放、跨区往返、暂停、后台和反复进入；无明显卡顿、持续白洞或内存增长 |
| 手机限制 | 入口隐藏，直接访问不初始化场景、不下载田园图和渲染代码 |

资源成本、历史检查与后续性能计划见 [性能](performance.md)。当前不继续验证性能，多组场景形成后再安排。
阶段顺序与交付方式见 [制作与验收](production.md)。图片生成、代码构建、
概念总览出现代表物，都不能证明完整内容、动作或作者视觉验收已经通过。
