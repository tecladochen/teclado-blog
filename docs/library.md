# 书影音：数据录入与维护

页面为 `/library`，入口在页脚。用于回看读过的书、看过的电影与剧集，以及喜欢的专辑。

## 开始整理真实数据

数据分别放在三个 JSON 数组文件中：

| 文件 | 内容 | 最少必填字段 |
| --- | --- | --- |
| `src/data/library/works.json` | 书籍、电影、剧集 | `id`、`type`、`title`、日期 |
| `src/data/library/artists.json` | 专辑关联的歌手或乐队 | `id`、`name` |
| `src/data/library/albums.json` | 喜欢的专辑 | `id`、`title`、`artists` |

可复制的模板在 [library-templates/](./library-templates/)：含三种作品、歌手和专辑示例，不会显示到页面上。
当前已录入 8 本书、12 部电影、5 部剧集，以及许嵩的五张专辑。新增作品继续添加到现有数组，不覆盖其他已录入条目。
首批书影均为作者确认已完成的历史补录。书籍完成日期分散记录在 2024、2025、2026 年，剧集集中记录在 2025、2026 年，均按作者确认的方式作为正式记录保留。电影继续按 `releasedOn` 的上映日期展示。出版／上映／首播日期保留在独立的 `releasedOn` 中，`addedOn` 只保留录入时间。后续新增作品直接填写自己的完成日期 `completedOn`。
封面来源与版本说明见 [书影封面目录](../src/assets/library/works/README.md)。

1. 先填作品名称、作者或导演、完成日期，不需要一次补齐所有封面。
2. 录入音乐时先填歌手，再在专辑的 `artists` 中引用歌手的 id。
3. 图片放入 `src/assets/library/`，补上对应的 `cover` 路径。
4. 本地查看 `/library`，完成后运行 `pnpm lint` 和 `pnpm build`。

每个文件内的 id 必须唯一，使用小写英文、数字和连字符，例如 `book-my-title`、`movie-my-title`、`artist-my-name`、`album-my-title`。
重复或缺失 id 会报错，不会静默覆盖或丢失数据。JSON 不支持注释或尾随逗号。
可选字段没有内容时直接省略，不填写空字符串。数组为空时使用 `[]`。

## 书籍、电影、剧集：`works.json`

最简条目：

```json
[
  {
    "id": "book-my-title",
    "type": "book",
    "title": "作品名称",
    "completedOn": "2026-10"
  }
]
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `id` | 是 | 稳定且唯一的标识，不随着标题修改而改变 |
| `type` | 是 | `book` 书籍、`movie` 电影、`series` 剧集 |
| `title` | 是 | 作品名称，剧集建议按季录入 |
| `completedOn` | 日期二选一 | 个人读完或看完的日期，优先用于显示与排序；接受 `YYYY`、`YYYY-MM`、`YYYY-MM-DD` |
| `releasedOn` | 日期二选一 | 出版／上映／首播日期；历史补录不知道完成时间时使用，精度同上 |
| `creator` | 否 | 作者、导演或动画原作／制作团队；多人可写成一个字符串，如“姓名一 / 姓名二” |
| `cover` | 否 | 本地封面路径，相对 JSON 文件，例如 `../../assets/library/my-book.webp` |
| `note` | 否 | 自己写的简短随记，建议一两句话 |
| `url` | 否 | 作品介绍或自己的文章地址，须为完整 HTTP／HTTPS 地址 |
| `status` | 否 | 默认 `completed`；兼容旧数据的 `in-progress`、`planned`，这两种状态不公开展示 |
| `addedOn` | 否 | 旧数据的加入日期，可省略；不影响已完成作品的排序 |

日期只填自己确定的精度，例如只记得年份就填 `2023`，不用编造月或日。日期必须真实有效。
已完成作品必须有 `completedOn` 或 `releasedOn`；明确填 `in-progress` 或 `planned` 的作品不填完成日期。
同一作品重读或重看，可使用另一个 id 录入一次，保留新的完成日期。
作品按个人完成日期（优先）或发布时间倒序展示；相同日期按 JSON 数组顺序展示。发布时间保持独立字段，后续添加完成日期时无需删除它。

完整条目示例（封面需先放入对应路径，链接替换为自己的地址）：

```json
{
  "id": "book-my-title",
  "type": "book",
  "title": "作品名称",
  "creator": "作者姓名",
  "completedOn": "2026-10-10",
  "cover": "../../assets/library/my-book.webp",
  "note": "自己写下的阅读随记",
  "url": "https://blog.teclado.cn/posts/my-review/"
}
```

## 歌手或乐队：`artists.json`

```json
[
  {
    "id": "artist-my-name",
    "name": "歌手或乐队名称"
  }
]
```

只需 `id` 和 `name`。不会生成独立歌手列表或排名；原有可选头像字段仍兼容。

## 专辑：`albums.json`

```json
[
  {
    "id": "album-my-title",
    "title": "专辑名称",
    "artists": ["artist-my-name"]
  }
]
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `id` | 是 | 专辑唯一标识，同名专辑用不同 id 区分 |
| `title` | 是 | 专辑名称 |
| `artists` | 是 | 至少一个歌手 id，引用 `artists.json`，按希望显示的顺序排列 |
| `cover` | 否 | 本地封面路径，例如 `../../assets/library/my-album.webp`，建议方图 |
| `coverScale` | 否 | 默认 `1`；原图自带外框时可略微放大、居中裁切展示，例如 `1.16`，范围 `1`～`2` |
| `language` | 否 | 可保留华语、英语、日语等资料；页面不展示此字段 |
| `note` | 否 | 喜欢这张专辑的原因，建议一两句话 |
| `addedOn` | 否 | 收藏日期，可精确到年或月；有日期的按倒序展示，无日期的排在后面；同日期或无日期按文件中的顺序 |
| `url` | 否 | 完整 HTTP／HTTPS 收听链接，在新窗口打开 |

合作专辑可填写多个歌手 id，例如 `["artist-one", "artist-two"]`。同一张专辑不能重复关联同一位歌手。
不存在的歌手引用会在构建时明确报错。无需填写曲目、评分、播放量或统计字段。

## 展示与图片规则

- 分类为全部、书籍、电影、剧集、音乐。「全部」只包含书籍、电影与剧集。
- 书籍和影视按展示日期的年份分组、日期倒序；音乐只展示专辑。日期旁注明出版、上映、首播或读完／看完。
- 分类通过现有卡片切换，不重新请求页面；沿用轨迹的 120ms 淡出、200ms 淡入，连续点击以最后一次选择为准。系统设置减少动态效果时直接切换。当前分类保存在 URL 中，支持刷新和分享。
- 方向键、Home、End 可以切换分类，键盘焦点不会触发额外滚动。
- 没有封面的条目展示固定比例占位图，不影响布局；没有链接的内容不显示无效点击入口。
- 封面支持 JPG、PNG、WebP；图片路径从 JSON 文件所在目录计算，路径大小写须一致。
- 构建时生成最多 160、240、360、480px 的 WebP，较小封面以原图宽度为上限，不强行放大。浏览器按实际尺寸与屏幕像素密度选择；新增原图建议至少 480px 宽。
- 书籍和影视按 2:3、专辑按 1:1 居中裁切铺满，避免容器留白；本地原图保留。作者／导演为单行，超出省略，悬停可查看完整名字。首屏封面提前加载，其余封面懒加载。
- 页面没有编辑表单，文件修改后需构建发布。字段校验以 `src/content.config.ts` 为准。

`pnpm exec tsx scripts/create-library-demo.ts` 可重新生成虚构示例。检测到非 `demo-` 内容时会停止，以免覆盖真实收藏。
