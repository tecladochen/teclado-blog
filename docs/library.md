# 书影音：方案与维护

## 定位与入口

个人书架、观看记录和音乐偏好。入口放在页脚，与足迹并列；页面为 `/library`。
顶部导航、文章列表和主 RSS 保持现有结构。

页面顶部统一为「全部／书籍／电影／剧集／音乐」一行分类，默认展示全部已看记录。
右侧使用观看状态下拉框；音乐的搜索放在歌曲列表旁。页面不显示示例提示。
不设置年度目标、计划进度、评分、短评或文章关联。

## 书与影视

- 支持书籍、电影、剧集，小封面网格展示作品名和作者／导演。
- 状态为已看、在看、想看，默认已看。想看只表示收藏，不要求安排时间。
- 已看按完成年份分段、时间倒序，让书架有明确的回看节奏；在看和想看按加入时间倒序，不绑定年份。
- 剧集建议每季一条记录。动画和纪录片按电影或剧集归类，漫画、有声书归书籍。
- 已看书架下方提供按完成年份分组的条形图，统计随作品分类变化。
  点击年份可查看对应记录，再次点击或「所有年份」取消，切换状态时清除年份。
  剧集统计以记录为单位，不设置独立的第二排筛选。
- 更新状态时修改同一条记录；重读／重看如果希望保留两次经历，可新建不同 id 的记录。

## 音乐

- 页面顺序为收藏统计、喜欢的歌手、精选歌曲。统计基于自己维护的收藏记录。
- 顶部显示歌曲、歌手和专辑总数；专辑按主歌手和专辑名识别，没有专辑的单曲不计入专辑数。
- 歌手收藏分布按收录歌曲数排序，可以看到收藏集中在哪些歌手；合作歌曲分别计入各位歌手，歌曲总数只计一次。
- 每年新收藏按 addedOn 的年份统计，每首歌只计一次，不推算播放次数或收听时长。
- 点击图表或歌手，会在下方显示对应歌曲；再次点击或「全部歌曲」恢复。每次只保留一个筛选条件，搜索会清除图表筛选。
- 歌手列表保留个人排名，数组顺序决定排名，与收藏数量分开。
- 歌曲按收录时间倒序，展示小封面、歌名、歌手、专辑、收藏年份和外部收听链接。手机端优先展示歌名与歌手。
- 支持搜索歌名、歌手和专辑；不设置音乐的完成状态。

## 数据录入

三个 JSON 文件都以数组存储，目前填有虚构示例，用于确认布局和图表效果。
示例的 id 均以 `demo-` 开头，图片在 `src/assets/library/demo/`。
正式使用时替换这批记录及对应封面即可，页面不展示数据来源提示。
可通过 `pnpm exec tsx scripts/create-library-demo.ts` 重新生成示例，该命令会覆盖示例数据；
检测到非示例记录时会停止。示例的收听链接指向 example.com，仅用于展示按钮布局。
字段校验以 `src/content.config.ts` 为准；录入后运行 `pnpm lint` 和 `pnpm build`。
这是静态博客，文件修改需要重新构建、发布才能上线，没有网页编辑或自动同步。

### 作品：`src/data/library/works.json`

下面是结构示例，作品信息和日期须自行替换。

```json
[
  {
    "id": "example-book",
    "type": "book",
    "title": "作品名称",
    "creator": "作者姓名",
    "cover": "../../assets/library/example-book.jpg",
    "status": "completed",
    "addedOn": "2026-10-08",
    "completedOn": "2026-10-08"
  }
]
```

- `type`：`book`、`movie`、`series`。
- `status`：`completed`（已看）、`in-progress`（在看）、`planned`（想看）。
- `id`、`type`、`title`、`status`、`addedOn` 必填；id 使用小写字母、数字和连字符，在作品文件内唯一。
- 已看必须填写 `completedOn`；其他状态不填写它。
- 日期接受有效的 `YYYY`、`YYYY-MM`、`YYYY-MM-DD`，历史记录无需编造具体日期。
- `creator`、`cover` 可选；建议补齐封面，没有封面时显示类型占位。

### 歌手：`src/data/library/artists.json`

```json
[
  {
    "id": "example-artist",
    "name": "歌手姓名",
    "avatar": "../../assets/library/example-artist.jpg"
  }
]
```

`id`、`name` 必填，头像可选。调整数组顺序即可调整排名，无需填写 rank。
歌手须先加入这里，歌曲才能引用对应 id。

### 歌曲：`src/data/library/songs.json`

```json
[
  {
    "id": "example-song",
    "title": "歌曲名称",
    "artists": ["example-artist"],
    "album": "所属专辑",
    "cover": "../../assets/library/example-album.jpg",
    "language": "华语",
    "addedOn": "2026-10-08",
    "url": "https://example.com/song"
  }
]
```

`id`、`title`、`artists`、`addedOn` 必填，其余可选。
`artists` 至少一位，同一首歌不可重复引用同一位歌手。
`albumArtist` 可选，填写专辑主歌手 id；未填写时使用 artists 中的第一位。
合作歌曲与其他专辑歌曲使用相同主歌手即可计入同一专辑。没有 album 的不计入专辑数。
`language` 保留为可选资料字段，目前不用于展示或统计。`addedOn` 表示收进收藏的时间，用于年度新增统计；历史记录可只填写年份。
`url` 支持 HTTP／HTTPS，点击后在新窗口打开。

## 封面与头像

将原图放进 `src/assets/library/`（首次使用时创建目录），JSON 中使用相对路径。
推荐封面使用 JPG、PNG 或 WebP，歌曲可共用同一张专辑封面。
构建时由 Astro 转为宽 240px、质量 65 的 WebP，头像宽 96px，按需懒加载。
实际文件大小取决于图片细节，不强制固定 KB；不需要手动维护第二份缩略图。

## 后续扩展

数据积累后再考虑搜索、批量导入和更便捷的录入工具。音乐可以增加专辑信息或更多分布统计，
但统计必须基于实际维护的数据，不推算听歌频率。手机录入需要另行设计存储和发布流程。
